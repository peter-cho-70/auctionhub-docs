# 지도 · 임장 동선 설계

> 기준일: 2026-10-25 · 구현: `src/components/scout-map.tsx`, `scout-route-panel.tsx`, `src/lib/direction/route.ts`, `route-settings.ts`, `src/lib/map/scout-address.ts`, `src/app/api/scouting/geocode/`

## 1. 목적

임장 후보를 지도에 표시하고, 방문 순서(임장 동선)를 만들어 하루 임장 계획을 세운다. 위치는 물건 데이터에 저장되어 백업에 포함된다(`searchDirection.coords`).

## 2. 위치 확보

| 순서 | 방법 | 정밀도 |
|---|---|---|
| 1 | 네이버 지오코딩 키가 있으면 사용 | 지번(정확) |
| 2 | OpenStreetMap Nominatim(키 없음, 초당 1건 제한, 서버에서 호출, 같은 주소는 메모리 캐시) | 동 단위 추정 |
| 3 | 사용자가 마커를 끌거나 「지도에서 지정」 | 직접 지정 |

- 주소 「대전 ○○구 ○○동 559-10 외 1개 목록」은 시·구·동·지번으로 나눈다(도·시·구, 세종처럼 구가 없는 경우 포함).
- Nominatim은 지번까지는 거의 못 찾아 **동 단위**가 보통이다. 지번을 넣어도 동 단위 결과를 돌려주므로, 정밀도는 질의가 아니라 **결과의 종류**(건물류 → 지번, 구 단위류 → 구, 그 외 → 동)로 판정한다(초기에 질의 기준으로 표시해 「지번」으로 잘못 보이던 버그를 수정).
- 한국 영역(위도 33~39, 경도 124~132) 밖의 값은 버린다.
- 화면에서 동 단위·구 단위 위치는 마커에 점선 테두리와 옅은 원(동 600m, 구 2.5km)으로 오차 범위를 보여 준다.

## 3. 동선 만들기

- **최단 순서**: 12곳 이하는 정확한 최적해(Held-Karp 동적계획, 열린 경로), 그보다 많으면 최근접 이웃 + 2-opt 근사. 출발지가 있으면 거기서 시작, 없으면 가장 짧은 시작점을 고른다.
- **직접 조정**: ▲▼로 순서 변경, 후보가 아닌 물건은 제외(후보에서 빼면 자동으로 빠짐). 순서는 이 브라우저(`auctionflow:scouting-route`)에 저장.
- **출발지**: 현재 위치(브라우저 위치 권한) 또는 지도에서 지정.
- **소요 추정**: 직선거리 × 1.3(도로 보정) ÷ 평균 30km/h + 곳당 현장 20분. 값은 화면에서 바꿀 수 있다. 구간별 직선거리 표시.
- **내보내기**: 곳마다 카카오 길찾기·네이버 지도 링크, 동선 전체 텍스트 복사.

## 4. 지도 표시

| 마커 | 의미 |
|---|---|
| 파란 번호 | 임장 동선에 들어가는 후보(순서 번호) |
| 초록 ✓ | 임장 완료 |
| 회색 점 | 그 밖의 저장 물건(선택해서 보기) |
| 주황 「출」 | 출발지 |

OpenStreetMap + Leaflet(`leaflet` 패키지). 마커 팝업은 사용자 데이터를 HTML이 아닌 DOM 노드로 만들어 삽입한다.

## 5. 검증

- 무작위 200회(3~7곳, 출발지 있음/없음)를 전수 비교: 근사만 쓸 때는 22회가 최적이 아니었고(최대 13% 길게) → 12곳 이하를 정확해로 교체한 뒤 **200회 모두 최적과 일치**.
- 실제 브라우저에서 2곳을 자동 위치(동 단위)로 찾고 번호 마커 1·2, 점선, 직선 10.4km(도로 약 13.5km)·이동 약 27분·현장 40분 표시를 확인.

## 6. 한계

- 자동 위치는 동 단위 추정 → 정확한 동선은 마커 보정이 필요(또는 지오코딩 키 설정).
- 거리·시간은 직선 거리 기반 추정이며 실제 도로·교통·주차를 반영하지 않는다.
- 다중 경유 길찾기 링크는 만들지 않았다(곳별 링크만 제공).
