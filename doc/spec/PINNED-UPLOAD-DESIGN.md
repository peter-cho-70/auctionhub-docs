# 고정물건 비공개 보관·화면 PDF 올리기 설계

> 기준일: 2026-10-28 · 상태: **구현·서버 경로 시험 완료**, 화면 캡처 단계는 실제 화면 확인 대기 · 위치: `src/lib/pinned/capture-page.ts`, `src/app/api/pinned/upload/route.ts`, `src/components/pinned-upload-button.tsx`

## 1. 목적

자주 보거나 임장에 필요한 물건의 상세·첨부를 **로컬이 아닌 곳(모바일 포함)에서** 볼 수 있게 한다. 사건번호·소유자·임차인 이름·유료 태인 PDF가 섞이므로 공개 문서 사이트(auctionhub-docs)에는 올리지 않고 **비공개 GitHub 저장소**(`peter-cho-70/auctionhub-pinned`)에 둔다.

## 2. 왜 공개 사이트에 로그인을 달지 않았나

공개 저장소·GitHub Pages는 정적 파일이라 로그인 화면으로 막을 수 없다(파일 주소만 알면 열림). 화면에 GitHub 비밀번호 입력창을 만드는 것도 부적절하다. 그래서 접근 제어를 GitHub 계정 로그인(비공개 저장소는 본인 외 404)에 맡긴다.

## 3. 저장소 구조

```
README.md                      물건 목록 표(사건번호 링크)
cases/<사건번호>/README.md      기본 정보·첨부 링크·메모·태인 상세 원문·「화면 캡처」 목록
cases/<사건번호>/*.pdf          태인 문서(감정평가서·건축물대장 등)와 화면 캡처 PDF
```

처음 올릴 때는 디스크 백업(2026-10-28) 기준으로 태인 문서가 있는 69건(약 550MB)을 올렸다. 고정 여부는 브라우저(localStorage)에만 기록돼 디스크 백업에 없어, 고정물건만 골라 올리려면 앱 화면에서 목록을 내보내야 한다.

## 4. 현재 화면 PDF 올리기

상세 화면의 「현재 화면 PDF 올리기」 버튼:

1. **캡처(브라우저)**: 현재 DOM을 복제하고 스타일시트를 한 `<style>`로 합친다. 입력값·체크·펼침 상태를 복제본에 옮기고, `blob:` 사진은 data URL로 바꾼다. 스크립트와 `data-no-capture` 요소(이 버튼)는 뺀다. gzip으로 압축해 `/api/pinned/upload?caseNumber=`로 보낸다.
2. **PDF(서버)**: 임시 HTML을 Chrome headless(`--print-to-pdf`, 머리글·바닥글 없음)로 PDF로 만든다.
3. **올리기(서버)**: `private/pinned-repo`(`.gitignore`의 `/private/`)에 저장소를 복제해 두고 `pull --rebase` → `cases/<사건번호>/화면_<날짜시각>.pdf` 저장 → 폴더 README에 링크 추가 → 커밋·푸시. 응답에 GitHub 링크를 돌려준다.

## 5. 안전 장치와 한계

- 이 컴퓨터(localhost)의 앱에서만 동작하고 Vercel에서는 꺼진다(PDF 생성·git 푸시를 하는 기능).
- 사건번호는 `[0-9A-Za-z가-힣-_]` 3~40자만 허용해 폴더 경로 이탈을 막는다.
- Mac의 Google Chrome 경로가 기본값이며 `CHROME_PATH`로 바꿀 수 있다. 저장소 주소는 `PINNED_REPO_URL`.
- git 인증은 이 컴퓨터에 이미 설정된 자격 증명을 쓴다(토큰을 앱에 저장하지 않음).
- 지도 타일 같은 외부 이미지는 인터넷이 있어야 PDF에 들어간다. 캡처는 스크롤·접힘 영역이 아니라 DOM 전체를 인쇄하므로 화면 모양과 쪽 나눔이 다를 수 있다.
- 시험: 시험 HTML로 PDF 생성·한글 본문·커밋·푸시와 잘못된 사건번호 거절을 확인했다(시험 파일은 삭제). 실제 상세 화면에서의 캡처는 미확인.
