# 내 데이터는 어디에 있나

> 기준일: 2026-10-25 · 같은 내용이 앱의 **데이터 탭 맨 위 「내 데이터는 어디에 있나」**에 현재 개수·용량과 함께 표시된다(`src/components/data-location-panel.tsx`).

## 결론 (3줄)

1. **물건 데이터는 서버가 아니라 이 브라우저에 있다**(IndexedDB, 설정은 localStorage). 클라우드(Supabase)를 연결하지 않았다면 다른 곳에는 없다.
2. **수집한 원본 파일(태인 사진·문서 PDF 등)만 이 컴퓨터의 프로젝트 폴더 `private/collector/`에 있다.** git에는 올라가지 않는다.
3. **물건 데이터는 브라우저 안(IndexedDB)과 브라우저 밖(이 컴퓨터 `private/backups/`)에 이중으로 자동 백업된다**(데이터 탭 → 백업·복구, 날짜별 복원). 브라우저 데이터가 지워져도 디스크 백업은 남는다. 사진·PDF·수집 원본 파일은 백업에 없다. 「처음부터 새로 시작」은 브라우저 안 백업만 지우고 디스크 백업은 남긴다.

## 저장 위치 한눈에

| 위치 | 무엇 | 지우는 방법 |
| --- | --- | --- |
| 브라우저 IndexedDB `auctionflow-app` → `auctionflow:v1` (예전에는 localStorage, 첫 실행 때 자동 이전) | ★ **실제 물건 데이터**: 물건, 임차인, 임대세팅, 분석, 체크리스트, 메모, 지식 노트, 강의 노트 편집본 | 데이터 탭 → 「처음부터 새로 시작」(물건만) 또는 물건 목록의 삭제 |

| 이 컴퓨터 `private/collector/taein-media/<키>/` | 태인 상세에서 받은 사진·그래프·문서 5종 PDF·인쇄본 | 물건 「완전 삭제」, 「처음부터 새로 시작」 |
| 이 컴퓨터 `private/collector/downloads/<사건번호>/` | 보스옥션 문서 수집분 | 위와 같음 |

| git 저장소 | 코드와 `docs/`만. **물건 데이터·수집 원본은 포함되지 않는다**(`/private/`는 `.gitignore`) | — |

## 주의

- **주소·브라우저마다 따로 저장된다.** `localhost:3000`, `127.0.0.1:3000`, 다른 포트, Chrome과 Safari는 서로 다른 저장소다. 목록이 비어 보이면 먼저 주소를 확인한다.
- 브라우저의 「사이트 데이터 삭제」·시크릿 창은 물건 데이터를 지우거나 따로 만든다.
- 서버의 `private/` 폴더만 지우면 물건은 남지만 서버에서 다시 읽는 원본(문서 다시 열기 등)이 없어진다. 물건 상세의 「다시 수집」으로 다시 받을 수 있다.
- 물건 상세에서 문서·사진을 열 때는 IndexedDB에 저장된 사본을 쓴다.
- 백업은 **앱을 열 때 · 변경 5분 뒤(30분 간격) · 삭제/전체 갱신/초기화/복원/클라우드 병합 직전**에 만들어진다. 복원은 현재 데이터를 교체하지만 교체 직전 데이터를 먼저 백업하므로 복원도 되돌릴 수 있다.
- 「처음부터 새로 시작」 시각보다 **오래된 백업은 목록·복원에서 제외**된다(예전 데이터가 되살아나지 않게). 샘플·시드 데이터는 없다.
- 예전 방식의 localStorage 스냅샷 키(`auctionflow:v1:snapshots`)는 앱이 기동할 때 한 번 지운다.
