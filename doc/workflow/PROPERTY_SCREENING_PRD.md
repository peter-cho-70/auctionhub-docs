# 물건 검색·평가 자동화 PRD (초안)

> 기준일: 2026-10-25 · 상태: **P1~P3 구현 완료**(P4 미구현) · 구현 내역은 [CHANGELOG](CHANGELOG.md) 참고
> 목적: 「남들이 귀찮아서 확인하지 않은 정보」를 앱이 대신 모아 주고, 사람은 마지막 판단에만 시간을 쓰게 한다.

## 결론 (3줄)

1. 좋은 방법은 **3단 깔때기**다: ① 목록 단계에서 싸게 거르고 → ② 서류가 오면 자동으로 위험 신호를 찾고 → ③ 남은 몇 건만 사람이 도면·현장으로 정밀 평가한다.
2. 자동화의 핵심은 「점수 매기기」가 아니라 **탈락 사유(레드플래그)를 근거와 함께 보여 주는 것**이다. 점수는 보조다.
3. 이 앱에는 이미 재료가 대부분 있다(태인 수집, 문서 5종 자동 저장, 층별 평면도 추출, 다가구 점수, 검색 체크리스트 11항목). 새로 만들 것은 **이 재료를 한 줄 판정으로 묶는 스크리닝 엔진**이다.

## 1. 전문가·자료 의견 종합

> **출처의 한계(중요)**: 웹 검색으로 모은 자료는 대부분 개인 블로그·교육 사이트·언론 기사다. 이름이 확인되는 특정 전문가의 의견을 인용한 것이 아니며, 작성 시점이 불분명한 글도 많다. 아래는 **여러 자료에서 반복해서 나온 공통 원칙**을 정리한 것이고, 수치는 모두 「확인 필요」다. 사용자의 강의 메모(곰물주 마인드)는 별도 항목으로 표시했다.

### 사용자 강의 메모(곰물주 마인드)에서 가져온 원칙

- **추측 금지**: 면적만 보고 가구 수·룸 타입을 추정하지 않고 도면·건축물대장·호별 면적으로 확인한다.
- **평균값 착시 경계**: 동네 평균 월세가 낮아도 준신축·1.5룸·주차·엘리베이터면 1등 상품일 수 있다.
- **정보 차이는 손이 많이 가는 곳에서 생긴다**: 도면, 룸 구성, 실제 공실, 관리 상태, 비교 표준지, 도로 지분.
- **조급 금지**: 꾸준한 검색이 핵심. → 앱은 「오늘 볼 만한 물건」을 매일 같은 기준으로 걸러 주는 역할.

> 사용자 메모의 「정보 차이는 귀찮은 항목에서 난다」는 이 PRD의 설계 원칙이 된다: **귀찮은 항목일수록 앱이 먼저 모으고, 못 모으는 것(실제 공실·관리 상태)은 임장 체크리스트로 넘긴다.**

## 2. 설계: 3단 깔때기

```
[1단 목록 거르기]  태인/대법원 검색 결과 수십~수백 건
   ↓  (서류 없이 목록 필드만으로, 수 초)
[2단 서류 스크리닝] 후보 10~20건 → 문서 5종·상세표 자동 수집 후 레드/옐로/그린 판정
   ↓  (자동, 건당 1~2분)
[3단 정밀 평가]    그린·옐로 3~5건 → 도면·세대수·시세·수익률·입찰가 역산, 임장 체크리스트
   ↓  (사람)
 입찰 결정
```

### 1단. 목록 거르기 (이미 있는 필드로 가능)

사용하는 필드: 용도, 입찰일, 감정가, 최저가, 유찰 회차(`round`), 최저가율(`ratio`), 법원, 특이사항(`notes`).

| 규칙 | 기본값(조정 가능) | 판정 |
| --- | --- | --- |
| 용도 = 다가구 계열 | 다가구주택 | 아니면 제외(설정으로 해제) |
| 입찰일 | 오늘 이후 14일 이내 | 지났으면 제외 |
| 유찰 회차 | 0~2회 정상, 3회 이상 | 3회+ → 옐로(사연 확인), 5회+ → 레드 |
| 특이사항 키워드 | 지분, 유치권, 법정지상권, 선순위, 분묘, 위반건축물 등 | 레드/옐로 + 키워드 표시 |
| 최저가 / 감정가 | 사용자 예산 상한 | 초과 제외 |

→ 결과: **「오늘 볼 만한 물건」 목록** (입찰일 가까운 순 정렬은 이미 적용됨).

### 2단. 서류 스크리닝 (문서 5종 + 상세표 자동 수집 후)

| 신호 | 판정 근거(자료) | 등급 |
| --- | --- | --- |
| 대항력 있는 임차인(전입일 ≤ 말소기준권리일) + 보증금 미배당 | 매각물건명세서·태인 임차인표 (`TaeinTenant.hasOpposingPower`, `assumedAmount`) | 인수액 > 0 → 레드 |
| 선순위 권리 인수(전세권·가처분·지상권 등 말소 안 되는 등기) | 등기부(건물·토지) 권리 표 | 레드 |
| 유치권·법정지상권·지분·분묘 문구 | 현황조사서·명세서 비고·감정평가서 「제시외건물」 | 옐로/레드(키워드, 사람 확인 필수) |
| 위반건축물 | 건축물대장 요약 (`ledger.hasViolation`) | 옐로 |
| **세대수 불일치**: 건축물대장 가구수 vs 임차인 수 vs 도면 호실 수 | 건축물대장·임차인표·**층별 평면도(자동 추출됨)** | 불일치 → 옐로 (강의 메모 「추측 금지」) |
| 감정가가 시세보다 높음 | 감정가 vs 인근 실거래·낙찰통계 | 안전마진 음수 → 옐로 |
| 임차인 보증금 합계가 최저가에 근접 | 보증금 합계 / 최저가 (이미 `depositRiskWarnings` 있음) | 옐로 |
| 배당요구 종기일·명세서 변경(변경/취하 이력) | 태인 기일내역 | 옐로 |

판정 규칙: **레드가 하나라도 있으면 레드**, 옐로만 있으면 옐로, 신호 없고 필수 서류가 다 있으면 그린. 필수 서류가 빠지면 「판정 불가」(그린으로 두지 않는다).

각 신호에는 반드시 **근거(문서명·쪽·원문 발췌)** 를 붙인다. 근거 없는 판정은 사람이 못 믿는다.

### 3단. 정밀 평가 (기존 기능 연결)

- **입찰가 역산 계산기**: 시세 − (취득세·등기·명도·수리·이자) − 목표수익 = 최대 입찰가. 시세·낙찰통계는 수집된 표에서 자동 채움, 비용·목표수익은 설정값.
- **정보 격차 체크리스트 자동 생성**: 강의 메모의 항목(도면·룸 구성·실제 공실·관리 상태·비교 표준지·도로 지분)을 물건별로 「자동 확인됨 / 사람이 확인할 것」으로 나눠 보여 준다. 기존 `multiFamilyAnalysis` 체크 11항목과 연결한다.
- 기존 다가구 점수(`computeMultiFamilyScore`)는 유지하고, 스크리닝 등급과 나란히 표시한다.

## 3. 사용자에게 보이는 모습

- 태인/대법원 검색 결과 표에 **등급 배지(레드/옐로/그린/판정불가)** 와 한 줄 사유 (예: `대항력 임차인 인수 1.2억`).
- 물건 상세 상단에 **스크리닝 요약 카드**: 등급, 신호 목록(근거 링크 → 같은 창에서 문서 열기), 사람이 확인할 항목.
- 목록 화면에 「오늘 볼 만한 물건」 보기(그린/옐로만, 입찰일 순).
- 규칙 값(유찰 상한, 예산, 목표수익률, 키워드)은 한 화면의 **설정**에서 바꾼다.

## 5. 위험과 한계

- **자동 판정은 보조다.** 키워드 탐지는 오탐·누락이 있다(「유치권 없음」도 키워드에 걸림). 레드/그린 모두 근거를 보여 주고 최종 판단은 사람이 한다.
- **법률 규칙은 바뀐다**(대출 한도, 취득세 중과, 임대차 보호). 규칙 값은 코드에 박지 않고 설정으로 분리하며, 기준 날짜를 함께 표시한다.
- 태인은 **동시 로그인을 한 곳으로 제한**한다. 자동 수집은 사용자의 다른 기기 세션을 끊을 수 있다.
- 수치(낙찰가율, 목표 수익률 등)는 출처가 블로그 수준이라 **내 데이터(과거 낙찰통계)로 검증** 후 기본값을 확정해야 한다.
- 개인정보: 문서에 임차인 실명·소유자 정보가 있다. 기존 방침대로 로컬(`private/`, 브라우저 저장소)에만 두고 외부 AI로 보내지 않는다.

## 6. 확인이 필요한 결정 (구현 전)

1. **P1부터 시작해도 되는가?** (권장: 예. 새 수집 없이 가진 데이터로 바로 판정 가능)
2. **내 기준값**: 예산 상한, 선호 지역, 목표 수익률, 유찰 몇 회까지 보는지 (없으면 위 기본값 사용).
3. **레드 물건을 목록에서 숨길지, 표시만 할지** (권장: 표시만, 기본 접힘).
